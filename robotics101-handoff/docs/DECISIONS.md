# Architecture decision log

## Adopted
- ADR-001: Implement locally before distributing to cloud (reduces initial integration risk).
- ADR-002: Use template-first deterministic animation; generated code is fallback only.
- ADR-003: Isolate all AI-generated code in tightly controlled render containers.
- ADR-004: Durable Functions for orchestration, Service Bus for worker dispatch; asynchronous versioned completion events.
- ADR-005: Postgres metadata + immutable blob content, SHA-256 IDs and lineage.
- ADR-006: FFmpeg for initial composition, not a paid generalized video framework.
- ADR-007: Require final artifact hash-bound human approval before any release.
- ADR-008: Scene-level caching and dependency-aware partial rerenders.
- ADR-009: Grok Bot optional editorial coordinator, not production control plane.
- ADR-010 (M01.3): Manim templates run as a subprocess per scene. The host picks the scene class from a fixed allowlist (`animation/manim_templates/SCENE_CLASSES`) and passes only validated parameters + duration as a JSON job file (`ROBOTICS101_SCENE_JOB`); the template re-validates against the registry. Each template scripts a fixed animation sequence quantised to whole frames, then a frozen-frame hold pads the clip to exactly `round(duration × fps)` frames. Templates use `Text` only (no LaTeX dependency). Consequence: scene clips are deterministic and composable on the `timing.json` timeline; in the production architecture this subprocess becomes the isolated render-worker boundary.
- ADR-011 (M01.4): Blender 3D scenes render headless with the **Workbench** engine (studio light `paint.sl`, shadows, 8× AA full / 5× preview) on CPU. Measured in the dev container (8 CPUs, no GPU, Blender 4.3.2) at 1920×1080: EEVEE Next ≈2.1 s/frame (≈47 min for 45 s), Cycles CPU 16 spp ≈1.6 s/frame and this build has no OpenImageDenoise, Workbench ≈0.45 s/frame single-process. Motion is planned in pure Python (`robotics101.kinematics`, also run on the host for a fail-fast `collisionCheck`), each motion frame is set explicitly and rendered to PNG by up to 4 parallel Blender processes, and ffmpeg encodes H.264 while cloning the last frame for the static hold (`tpad`) so the clip is exactly `round(duration × fps)` frames. 3-point lights are in the scene for EEVEE (`ROBOTICS101_BLENDER_ENGINE=eevee`) but Workbench ignores them. Consequence: ~6 min for scene-006 at 1080p, ~70 s preview; flat-ish "illustration" look rather than photoreal. Revisit (EEVEE/Cycles + GPU workers) when the cloud render worker exists.
- ADR-012 (M01.5): Composition is sync-by-construction. Each scene's length is its clip's actual frame count N; its audio is built sample-exactly to N × 1600 samples (48 kHz / 30 fps) — narration upmixed to stereo, EBU R128 integrated loudness measured on that signal → linear `volume` gain to −16 LUFS, brick-wall `alimiter` at −1.5 dBFS (`level=0`, latency-compensated), delayed by the lead-in, padded with silence, 5 ms edge fades. `clips/<id>.mp4` = scene video (stream copy) + AAC. `final.mp4` = clip video joined with the `concat` filter and re-encoded once (libx264 High, yuv420p, CFR 30, GOP 60, crf 20, +faststart) + the per-scene PCM mixes concatenated losslessly in Python and encoded once to AAC 192 kb/s. Hard cuts only (no crossfades), so `timing.json` needs no adjustment; captions are regenerated on the frame-quantised timeline. Two-pass `loudnorm` was rejected: with hot espeak peaks the linear second pass falls back to dynamic mode, which emitted silence in this chain on FFmpeg 7.1 (caught by the QA silent-audio gate). Manifest ↔ QA: the manifest is written first, QA verifies every entry except the QA reports themselves, then the report hashes are sealed into the manifest (`qa` re-run repeats this). Approval/publishing binds to `finalVideoSha256`; M01 bundles are always `publish.status = "not_published"`.
- ADR-013 (M01.5): The Blender avoidance scene takes its stop threshold from the episode's first `sense_think_act.thresholdMeters` (default 0.5 m) via a job context field `stopThresholdMeters` (not a template parameter), so the 3D demonstration obeys the rule the 2D scene teaches; thresholds beyond the 1.5 m sensor range fail planning.

- ADR-014 (M01.6): The publisher is a dry-run stub with no network code at all (no Google/OAuth libraries; an AST test forbids network imports). It binds everything to the SHA-256 of `final.mp4`: the bundle must match `manifest.json`, and an owner `approval.json` must name that exact hash; any change to the video invalidates the approval. Even with a valid approval it only writes `publish_plan.json` (`wouldUpload: false`); real upload is refused until M06. Uploads default to `privacyStatus: private` and declare `containsSyntheticMedia` while the narration is synthetic; `selfDeclaredMadeForKids` is left for the owner.

- ADR-015 (M02.1, owner-approved cartoon direction): Episodes become a Saturday-morning 2D cartoon (cast Bolt, Maya, Nib; `docs/PLAN-cartoon.md`). Contract v1.1 (`contracts/episode.v1.1.schema.json`) replaces per-scene `narration` with typed `beats` (line / sfx / action / pause / music) on engine `cartoon`; v1.0 specs stay valid and keep the M01 pipeline (cartoon specs are refused by narrate/render with exit 3 until M02.6). Characters live in a versioned registry (`characters/registry.json`, hashed into manifests later) that pins each speaker's ElevenLabs voice id/model/settings plus Kokoro and espeak fallbacks; it must never contain credentials. The audience is declared per episode (`publishing.madeForKids`, true for the pilot): the publish plan copies it to `selfDeclaredMadeForKids`, and kid-safe wording is an error for made-for-kids episodes. Every spoken quantity with a unit (digits or words) must equal a number in that scene's parameters ("teaching-fact lint"), and the stop threshold must be identical across scenes.
- ADR-016 (M02.2): Cartoon voices are synthesized per line by a backend chain chosen once per episode: ElevenLabs (owner's paid account; production) when `ELEVENLABS_API_KEY` is set, else Kokoro-82M (local, Apache-2.0 weights via kokoro-onnx), else espeak-ng; voices are never mixed within an episode, and a failing ElevenLabs call is an error (not a silent fallback). The key is read from the environment at call time only; it is never stored, logged, cached, put in a manifest, or echoed (errors are redacted), and voice QA hard-fails if the key string appears in any artifact. Raw provider audio is cached by SHA-256 of provider + voice id/model/settings + text (character fx and trimming are applied after the cache, so tuning them never re-bills); an ElevenLabs ledger records billed characters, and a per-run budget (`ROBOTICS101_ELEVENLABS_MAX_CHARS`, default 8000) is checked before the first call. Scene durations are now driven by the dialogue timeline (timing.json v2, whole frames) instead of padded holds; `durationTargetSeconds` is a pacing target checked by QA.
- ADR-017 (owner direction, 2026-11-22): before any full-episode ElevenLabs voicing, short sample lines for Bolt and Maya are produced (`voices samples`) and the owner approves them; `voice` refuses billable synthesis until each speaker's `voice.elevenlabs.approved` is true. The M01 Blender obstacle scene is kept as a "robot-cam" cutaway inside the cartoon rematch scene (restyled to the cartoon palette), with the 2D cartoon staging as the main view; the 0.5 m threshold is shared.
- ADR-018 (M02.6): SFX timing — an sfx beat right after an action (or chained to such an sfx) is anchored to that action and adds no time: start-type sounds fire at the action start, impacts (bonk/boing/skid/clap) at its end, echo 0.4 s after its ping; only free-standing sfx (e.g. after a line) advance the timeline by 0.45 s. `sound_s` per sfx is recorded for the mixer. Robot-cam sync — scene 7's 2D approach is planned so its stop sample lands on the ping beat and reads the same truncated value as the Blender clip's stop (0.47 m for the 9 s clip; both < 0.5 m, never firing a sample early); the clip is spliced over [stop − 2.6 s, stop + 1.9 s] with its stop frame aligned to the 2D stop, keeping the scene frame count.
- ADR-019 (M02.8): `render` on a schema-1.1 spec runs the cartoon pipeline (validate → voice → cartoon scenes incl. the Blender robot-cam → generated music/SFX mix → one-pass compose of scenes + mix.wav (H.264 High CRF 20 `-tune animation`, AAC 192k, faststart) → cartoon key-art thumbnail → manifest → cartoon QA → sealed). The manifest records `characterRegistry` {sha256, rigVersion (registry), drawingVersion (code `rigs.RIG_VERSION`)}; QA hard-fails if they differ from the current registry/code or from the registry the lines were voiced with. `--tts auto` skips ElevenLabs while any speaking character's ElevenLabs voice is unapproved (falls back to Kokoro, then espeak, recording why); an explicit `--tts elevenlabs` is refused until approval (ADR-017). Cartoon QA adds hard teaching-fact checks (one shared threshold; the drawn rule board / rematch stop / sensor range / servo angles / quiz match the spec; robot-cam cutaway present), presence ≥ 0.8, voice identity per registry, madeForKids declared, thumbnail 1280×720; lip-sync agreement < 0.9 is a warning.
- ADR-020 (M03.1, owner feedback on the M02.8 cut): pipeline defaults apply to every cartoon episode through `cartoon/episode.py::expand_episode(spec, registry)` — an idempotent expansion run by `render`, `voice` and `render-cartoon`; the bundle's `episode.json` is the expanded spec (the author's file is kept as `episode.source.json`). First default: a generated `cartoon_character_intro` scene ("Meet the crew"), on unless `intro.enabled` is false, placed after a cold-open first scene (`intro.position` `after_cold_open`, or `start`). Its content comes only from the character registry: every `main` character needs an `intro` block (tagline, entrance and signature action from its own action list, emotion, and a line by a speaking character that says its display name — validated by `registry_problems`). Staging: entrance from off stage, rotating spotlight, nameplate (display name in the registry caption colour + tagline) while the name line plays, then a lineup. QA hard checks `intro.present` (right position) and `intro.cast` (each main cast member on stage ≥ 0.8, nameplate = registry name for ≥ 1.5 s, name spoken while the plate is up); presence QA now starts at each character's entrance (`enterAt`).
- ADR-021 (M03.2): scene transitions and concept title cards are expansion defaults. Every scene after the first gets a resolved `transitionIn` (`wipe`, `iris`, `slide`, `character` = Nib pulls a curtain, or an explicit `cut`); `auto` = iris into the intro, then the cycle wipe → character → slide → iris; `transitions.seconds` (0.8) is split into an out-half drawn over the last frames of the outgoing scene and an in-half over the first frames of the next, so durations/audio/captions do not change and the fully covered frame is identical on both sides of the concat point. The mixer adds a generated `swish` centred on each boundary. Concept markers (scene `concepts[{id,title,subtitle,icon,beforeBeat}]`) insert a 2.8 s `concept_sting` music beat before the marked beat; the engine shows an animated full-screen card (live icon: robot loop, gear+battery, ping, stop sign, servo sweep) for exactly that beat. QA (pixel-level, `cartoon/vision.py`): `transitions.no_hard_cuts` (hard: grey diff across each boundary ≤ 4, cover/reveal visibly animate ≥ 10; explicit cuts → warning) and `concepts.cards` (hard: every marker has a ≥ 2 s card, titled as in the spec, gone before the teaching line, visible in final.mp4). Validation rejects duplicate concept ids and out-of-range `beforeBeat`.
- ADR-022 (M03.3): "nobody is ever static" is a property of the motion system, not of individual scenes. `Performer.life` (default on) adds, as pure functions of t: breathing bob + weight-shift sway (×2.2 for tiny Nib when landed), slow arm drift, seeded eye glances every ~1.5–3 s, extra lean while talking, listener reactions (scene dialogue registers every non-speaker via `listen`: nods + lean toward the speaker, a bounce when the line ends), anticipation (0.25 s wind-up before a real move) and damped follow-through overshoot after it settles (micro-keyframe chains ignored). QA is analytic (`cartoon/liveliness.py`): each character is reduced per frame to key points (body, head, hands, eyes incl. gaze/blink, mouth) in 1080p pixels; a run is static while no point moves > 6 px from the run start; frames under transitions, concept cards, cutaways, before entrance or with presence < 0.5 are excluded. The render report stores `liveliness` per scene and `characters.alive` hard-fails any run > 1 s (warning on pre-M03.3 bundles without data).
- ADR-023 (M03.4): concept illustrations are animated, never stills. The robot-family album plays looping vignettes (`cartoon/vignettes.py`, pure functions of t): a vacuum sweeping dust and bumping the walls (squash + star), a rover crossing scrolling bumpy terrain (spinning wheels, tilt, dust puffs) and a factory arm doing pick-and-place with 2-link elbow-up IK; concept cards already carry live icons (ADR-021). Staging registers each animated illustration region (`scenes.json` `illustrations`, normalised boxes + time window). QA streams final.mp4 once at 384×216 grey (`hold_runs`, report `qa/static_holds.json`): `illustrations.animated` hard-fails a region whose mean change vs the start of a run stays < 1 grey level for > 2 s, and `video.no_long_holds` hard-fails any > 2 s stretch where fewer than 30 pixels change by > 10 levels (the whole picture frozen). Out-transition frames are excluded from region windows.
- ADR-024 (M03.5): burned-in kid subtitles are on by default (`subtitles.burnIn`, `fontSizePx` em size, default 58 px at 1080p, QA floor 48). Font: Baloo 2 (Ek Type, SIL OFL 1.1, no Reserved Font Name) bundled unmodified in `assets/fonts/` with its OFL.txt and listed in `assets/LICENSES.json`; libass uses its named Bold instance. Cues are built from timing.json dialogue lines (no speaker prefix; text in the speaker's registry `captionColor`, thick dark outline + soft shadow), wrapped by measured width (PIL with libass's size convention, 80 % of the frame, balanced 2-line breaks) and split into sentence/clause/word chunks timed by character share when a line needs > 2 lines. Placement: bottom (64 px margin, inside the 5 % action-safe area) unless a registered teaching visual (`scenes.json` `keepouts`: rulers, rule board, readouts) is on screen under it → raised just above it, else top. Written as `subtitles.ass` + `subtitles.json` (cue boxes) and burned by ffmpeg/libass in the single compose encode (encode settings unchanged; it also covers the robot-cam cutaway); `captions.srt` (with speaker names) is still exported for YouTube. QA (hard): `subtitles.burned`, `subtitles.coverage` (every dialogue line covered without gaps), `subtitles.layout` (safe area, ≤ 2 lines, em ≥ 48 px, no keep-out overlap), `subtitles.visible` (sampled cues: speaker-coloured text pixels inside the predicted box in final.mp4).
- ADR-025 (M03.6, amends ADR-022/ADR-024 after reviewing the first M03.6 1080p cut): (1) listener nods and a new small attentive sway are scaled by the same per-character gain as the idle wiggle (`motion.SMALL_CHARACTER_GAIN`, Nib 2.2), because a perched Nib listening to a long line moved < 6 px for 1.07 s (QA `characters.alive` hard fail, scene-005). (2) Subtitle cues lifted off the plain floor (`raised`/`top` placement) sit over characters and props, so they get a rounded dark backing panel (`#1E1633`, ≈ 81 % opaque, 26/8 px padding, drawn as an ASS `\p1` shape on layer 0 under the text); the yellow (Maya) cue over Maya's shirt in scene-005 was hard to read. Bottom cues are unchanged. `subtitles.json` cues carry `panel`; QA `subtitles.layout` now also fails a raised/top cue without a panel or a panel overlapping a keep-out.
- ADR-026 (M04.1, amends ADR-016): ElevenLabs calls go through the official `elevenlabs` Python SDK (≥ 2.79) instead of hand-rolled urllib. Key loading: `ELEVENLABS_API_KEY` from the shell, else the project's gitignored `.env` via python-dotenv (`load_env`, never overriding an exported value; `ROBOTICS101_DOTENV` overrides the path and the test suite points it at a missing file and blocks real SDK clients). Model: `eleven_v4` (highest quality; 1.0 credit/char on the owner's Creator plan), which accepts only `stability` + `similarity_boost`, so the request (and therefore the cache key) keeps only the settings the model supports; pace/emotion come from the text. Synthesis uses `text_to_speech.convert_with_timestamps` (one billed call → audio + character alignment), output `mp3_44100_192`, seed 101. The alignment is cached next to the audio (`<key>.alignment.json`, so cached lines keep word timings for free) and written per line as `voice/lines/*.words.json` (words shifted by the measured edge-silence trim; referenced from timing.json `words`); Rhubarb still drives the mouth shapes. The cache key remains SHA-256 of provider + voice id + model + settings + output format + seed + text. Spend guards: the registry approval gate (`voice.elevenlabs.approved`) is unchanged, `robotics101 voice --tts auto` now also falls back to Kokoro while voices are unapproved (same rule as `render`), and `voices samples` / `voices audition` refuse to call the API without `--yes`. New `voices account` (plan, credits used/remaining, TTS models; no credits). Candidate library voices (unapproved): Bolt = Horatius (qXpMhyvQqiRxWQs4qSSB), Maya = Ember (WtA85syCrJwasGeHGH2p), alternates recorded in the registry; Nib does not speak (beeps are synthesized SFX).
- ADR-027 (M05.1): Explanations are shown illustration-first. A scene may carry `shots` — layout segments over inclusive beat ranges: `stage` (normal staging), `illustration` (full-bleed teaching visual; no character or one small corner character ≤ 10 % of the frame) and `solo` (exactly one character + a wide visual). When a scene has no authored `shots`, `expand_episode` fills them from `DEFAULT_SHOTS[template]`, anchored on beat kinds/sfx rather than episode text positions, so every episode using a template gets them; any line authored `explain: true` that no shot covers gets a generated `solo` of its speaker with the scene's concept icon. Lines inside illustration/solo shots are marked `explain: true`. Shots render as a top layer over the stage (which keeps running underneath so continuity, audio and timing are unchanged); the shot character is drawn from its live Performer, so lip sync and gestures carry over. QA `layout.illustration_first` (hard): every `explain` line lies inside an illustration/solo shot, illustration visuals ≥ 55 % of the frame, solo visuals ≥ 35 %, character counts per layout. Consequence: no dialogue/timing change (voice cache unaffected); characters hidden by a shot are excluded from liveliness QA.
- ADR-028 (M05.2, supersedes the placement part of ADR-024/025): The bottom 18 % of the frame is a reserved caption band. Layout keeps every character, teaching visual, readout and prop above it (characters already stand on the band's top edge; floor rulers moved behind the feet with labels above; rigs no longer dip below the ground when leaning; concept cards sized to clear it), and captions always sit inside it on a compact, see-through (≈ 58 % opaque) rounded box with a thin outline, 52 px em, one line preferred (two only when a one-line split would show a chunk < 1.2 s). Captions no longer jump above keep-outs (raised/top placement retired); instead `band_report` measures the actual geometry of every rig and overlay on sampled frames at render time and QA `layout.caption_band` fails on any intrusion (> 4 px), naming the staging function. Decorative shapes (light rays, backdrop bursts/dots) are explicitly tagged `decor` and may run under the band. Consequence: no timing/voice change; caption text is smaller but always on its own box over plain floor.
## Open decisions (do not block M01)

## Change control
When changing an adopted decision, append a new ADR with rationale, consequences and migration plan. Do not silently rewrite contracts or accepted behavior.
